# Changelog

## [Unreleased]

First release. branchout runs a Ruby method on many inputs, shows the branch arms that no input took, and writes tests that pin what the method does now. It never calls a model: an agent reads the frontier and proposes the next inputs.

- `branchout explore TARGET ENTRY` runs `Const.method` or `Const#method` on the inputs of a JSON file, plus literal mutations and seeded random samples. The report lists the input that took each arm, and the frontier: each arm no input took, with its condition, the direction that selects it, and the nearest input that reached it. The same inputs and flags print the same report, as text or as `--json`.
- `--emit-tests PATH` writes characterization tests for the inputs, as minitest or as RSpec (`--format rspec`). Each test pins the return value, or the error class and message, and starts with the arms its input took.
- `Branchout.explore` runs inside a test suite, so inputs can use the suite's factories and fixtures. In a Rails app each input runs in a savepoint that is rolled back.
- `branchout baselines` compares random samples, mutations, and the inputs file as separate rows.
- An agent skill in `skills/branchout/`.
- Ruby 3.3 or newer. No runtime dependency.
- A report prints an exception message as Ruby wrote it, on one line: only line breaks become spaces, so the blank String a `FrozenError` quotes keeps its spaces.
- `Branchout.explore` takes `requires:` as one path in a String too, as the README and its refusal write it.
- `--verbose` with `--json`, and `verbose: true` with `json: true`, are refused: the JSON report always holds every arm and the run settings.
- An input whose own Ruby raises before the entry runs, such as a bare `create` in a suite without `FactoryBot::Syntax::Methods`, stops explore with a message that names the input. Before, its error was listed as the entry's and pinned in the emitted test.
- Each input runs a second time, in a suite only when the first run was rolled back. A value made anew on each run, such as a generated UUID id, a factory sequence, or a `SecureRandom` token, is no longer pinned: a returned Hash pins only the keys that were the same both times, a value that differed as a whole gets no test, an error whose message differed is pinned by its class, and stderr names each such input. Before, the emitted test failed on its first run.
- A returned Hash whose generated id differed between two runs pins its other keys even when one holds a value with no literal, such as a `Time` or a record: RSpec writes `include(start_at: a_kind_of(Time))`, and minitest compares the literal keys with `slice` and checks each other key with `assert_kind_of`. Before, such an input got no test.
- The report lists under `NOT PINNED` (`arms_not_pinned` in the JSON report, `pinned: no` in `--verbose`) each covered arm whose every input returned a value that differed as a whole between two runs, so no emitted test checks it. An input that returned the same value both times is chosen as an arm's witness first. Before, such an arm counted as covered with no sign that no test pinned it.
- An input with `new`, `receiver`, `setup`, `kwargs`, or `block` may leave out `args` for a call with no positional argument. An input with none of them that leaves it out is refused with a message that says to write `"args": []`.
- `--verbose` and `verbose: true` leave out the settings and counts of a strategy that did not run, such as `random: 16` when only `inputs` ran. The JSON report still holds every setting.
- When rspec required a helper (from `.rspec` or `-r`) that loaded the target before the explore file, the refusal names that helper and says to run with `RUBYOPT="-rbundler/setup -rbranchout/coverage"`, which loads the copy the Gemfile names, as a path or git gem too, or with `rspec --options /dev/null -r <helper>` naming only the helpers that finished before the target loaded. The README says that `rspec -r branchout/coverage` does not help.
- An RSpec description names a Ruby call with keyword arguments, such as a factory call, by the keywords that differ between sibling inputs (`when b is "Y"`), not by its source cut at 80 characters, and never cuts the class of an error: a class that would push the text past 80 characters is named by its last segment (`raises PartNotFoundError`). A context of an input's `before` that calls the method a sibling's `before` calls is named the same way (`after FactoryBot.create(:part) with size: 1`).
- An input may give Ruby in `before`, which runs first in the input's savepoint and makes what the method reads, such as the rows a class method looks up. RSpec writes it as the `before` of the input's context, and minitest as the line before the call.
- An emitted RSpec file calls the class as `described_class` and pins `true`, `false`, and `nil` with `be(true)`, `be(false)`, and `be_nil`, and a Hash literal in either format has spaces inside its braces, as RuboCop and rubocop-rspec expect by default.
- The report lists each `<`, `<=`, `>`, and `>=` of the counted code under `BOUNDARIES` (`boundaries_not_counted` in the JSON report), since coverage cannot tell whether an input made the two sides equal, where `>` and `>=` part. The header says that the list comes from the source: a comparison stays on it after an input made its sides equal. Before, it told the reader to add such an input for every comparison.
- An emitted test pins a `Date` by its value (`Date.new(2026, 4, 1)`), and a `Struct` or `Data` whose members all have a literal by its class and members (`Slot.new(name: "a", on: Date.new(2026, 4, 1))`), in both formats and inside a Hash or an Array too. Before, each was pinned by its class, so a test passed when a date moved by a day.
- A file whose every input returned a value that differed between two runs skips one example, `pins no input` (`test_no_input_pinned` in minitest), that says so in the words of `NOT PINNED`. Before, it said that branchout discovered no input.
- An input's `before` of several lines is written with every line indented, in both formats, and an RSpec context names it by the lines that differ from its siblings', a call by its keywords that differ (`after FactoryBot.create(:membership) with enabled: false`). Before, only its first line was indented and the context was its source cut at 80 characters with a digest.
- An RSpec context of a receiver whose `new` differs from a sibling's only at some keywords is named by those keywords (`with start_at: Date.new(2026, 5, 1)`), and every emitted call passes its keywords in the input's order, as explore did. Before, the context was `new(...)` with its keywords sorted and cut at 80 characters, which could cut the keyword that differed.
- An Enumerable method called on self, such as `select(&:ok?)` in a class that includes `Enumerable`, counts the `each` that the target's file defines and the methods it calls. Before, an entry that reached its arms only through `each` reported `covered: 0 of 0 arms` with nothing under `NOT COUNTED`.
- `OPERATORS` leaves out an `@ivar ||=` or `@ivar &&=` on an instance variable that the file sets nowhere else. It memoizes across calls on one object, and each input builds its own receiver, so no input can vary its left side. One on an instance variable that `initialize` or another method sets, and a local's `||=`, stay listed.
- With `--emit-tests` (`emit_tests:`), the report lists under `PINNED BY CLASS` each part of a returned value that the emitted tests check only by its class, such as a `Time`, a record, or the `Enumerator` of a blockless `each`, with the first three inputs that returned it. Before, nothing said that a mutant that changed such a value would survive.
